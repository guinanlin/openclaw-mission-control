# 本地认证（用户名 + 密码）操作手册

本文档面向 **Self-Host 部署**时，希望使用「用户名 + 密码」登录 Mission Control 的操作人员，按步骤说明如何配置并完成首次登录。

---

## 1. 适用场景

- **Auth 模式**：仅当 `AUTH_MODE=local` 时，本地认证（用户名密码 + 绑定 Token）生效。
- **典型用途**：内网/自建环境，不想依赖 Clerk 等第三方登录，希望用固定账号密码登录，并为每个用户绑定一个 Access Token 供 API/网关使用。

若你当前是「只填一个 Access Token」的方式，按本手册配置后即可改为「先用户名密码登录，再自动使用该用户绑定的 Token」。

---

## 2. 前置条件

- 后端、数据库、前端已能正常运行（参见 [本地开发指南](./本地开发指南.md) 或 [Deployment](./deployment/README.md)）。
- 后端可读取到 `backend/.env`（或你实际使用的 env 文件）。

---

## 3. 配置步骤

### 3.1 设置认证模式

在 `backend/.env` 中确保：

```env
AUTH_MODE=local
```

### 3.2 配置「单 Token」可选兼容（可选）

若你**暂时仍想保留**「只用一个长 Token 登录」的兼容方式，可配置：

```env
LOCAL_AUTH_TOKEN=你的至少50字符的长Token
```

- 该 Token 不要包含 `|`，且不要写成 `admin|xxx` 等形式（避免被误当成种子用户）。
- 若你**只打算用用户名密码登录**，且通过下面的「种子用户」创建账号，可将 `LOCAL_AUTH_TOKEN` 留空或注释掉。

### 3.3 生成密码哈希（用于种子用户）

种子用户需要「密码的 bcrypt 哈希」，不能写明文密码。请在本机用 **bcrypt 库**生成（不要用 passlib，与当前 bcrypt 版本不兼容）。

在项目根目录下执行（将 `你的密码` 换成实际密码）：

```bash
cd backend && uv run python -c "import bcrypt; print(bcrypt.hashpw(b'你的密码', bcrypt.gensalt()).decode())"
```

示例（密码为 `MyPassword123`）：

```bash
cd backend && uv run python -c "import bcrypt; print(bcrypt.hashpw(b'MyPassword123', bcrypt.gensalt()).decode())"
```

输出为一串以 `$2b$12$` 开头的字符串，**整段复制**，后面配置会用到。

### 3.4 配置种子用户（启动时自动创建账号）

在 `backend/.env` 中增加或修改：

```env
LOCAL_AUTH_SEED_USERS=admin|上一步得到的bcrypt哈希
```

- **两段格式**（推荐）：`用户名|密码哈希`。启动时会自动为该用户生成一个「绑定 Access Token」，登录成功后接口会返回该 Token，前端会自动保存并使用。
- **三段格式**：`用户名|密码哈希|绑定的AccessToken`。若你希望该用户绑定一个自己指定的 Token（≥50 字符、不含 `|`），可写三段。多用户时用**英文逗号**分隔，例如：
  ```env
  LOCAL_AUTH_SEED_USERS=admin|$2b$12$xxx...|token1,operator|$2b$12$yyy...|token2
  ```
  第一个用户会自动设为超级管理员（super_admin），可用于后续在管理 API 中创建更多本地用户。

**示例（仅一个 admin，密码为 MyPassword123，自动生成 Token）：**

```env
LOCAL_AUTH_SEED_USERS=admin|$2b$12$wsRJhkYQnNM/4aCxmDuOFOn2CQH/hF5SQoWmOmkMcjIDijNBg1TtS
```

上面哈希对应的明文密码需与你登录时输入的密码一致（此处即 `MyPassword123`）。

### 3.5 启动或重启后端

- 若后端已在跑且带 `--reload`，保存 `.env` 后可能不会自动重载环境变量，建议**手动重启**一次后端进程。
- 启动后查看日志，应能看到类似：
  - `local_auth_seed.generated_token username=admin`（两段配置时）
  - `local_auth_seed.created username=admin user_id=... super_admin=True`

若出现 `local_auth_seed.skip invalid_entry`，说明格式有误，请检查是否少写了一段或多了不该有的字符（如 token 中含 `|`）。

## 4. 登录与使用

### 4.1 打开登录页

在浏览器中打开前端地址（如 `http://localhost:3000`），进入 Mission Control 登录页。在 Self-Host 模式下会显示「Local Authentication」登录框。

### 4.2 使用用户名 + 密码登录

- **用户名**：填写种子里配置的用户名（如 `admin`）。
- **密码**：填写生成该 bcrypt 哈希时使用的**明文密码**（如 `MyPassword123`）。
- 点击「Continue」或登录按钮。

成功后会跳转到应用内，前端会自动保存返回的 `access_token`，后续请求都会带该 Token，无需再操作。

### 4.3 使用 Access Token 直接登录（可选）

若你已有某个用户绑定的 Access Token（例如之前登录成功后在接口/存储中拿到），可在登录页选择「Use access token instead」，粘贴该 Token 直接登录，效果与用户名密码登录一致。

## 5. 常见问题

| 现象 | 可能原因 | 处理办法 |
|------|----------|----------|
| 登录提示「Invalid username or password」 | 1）种子用户未创建成功；2）密码与生成哈希时的明文不一致 | 查看后端启动日志是否有 `local_auth_seed.created`；确认密码与生成 bcrypt 哈希时使用的明文一致；必要时重新生成哈希并更新 `LOCAL_AUTH_SEED_USERS` 后重启 |
| 日志出现 `local_auth_seed.skip invalid_entry` | `LOCAL_AUTH_SEED_USERS` 格式不对（例如只有一段、或 token 中含 `\|`） | 使用两段 `username\|hash` 或三段 `username\|hash\|token`，且 token 中不要包含 `\|` |
| 种子用户已存在，想改密码 | 种子逻辑会跳过已存在的用户名，不会覆盖 | 通过管理 API（super_admin 账号）删除或更新该用户，或直接改数据库后重启；也可新增另一个种子用户 |
| 生成 bcrypt 时报错（passlib/bcrypt） | 使用了 passlib 的 hash | 按本文 3.3 节使用 `bcrypt.hashpw` 的一行命令生成，不要用 passlib |
